Add an Architectural Request Form

Architectural request forms give you a new way to collect more detailed information about your association member's architectural requests. By customizing the forms, you have more control over the information homeowners can submit. Forms can be customized to suit each association's needs, allowing you to cut down or even eliminate the amount of back-and-forth correspondence between the management company and homeowners.

More Information

If you need to edit an architectural request form, you do not need to complete the full process detailed here. For details about input fields you may want to edit, refer to the tables throughout this topic.

Related Privileges

Group Privilege Column
Associations Manage Architectural Request Forms Enabled

For more information, refer to Control User Access.

To add a new architectural request form, go to arrow_forward Services arrow_forward Community arrow_forward Architectural Request Forms and click Add Architectural Request Form in the top right.

Step 1: Enter General Information

The following fields are available on the General tile of the form:

Field Description

Form Name

A unique name for the form to display in Rent Manager.

Display Name

A unique name for the form as it displays on Tenant Web Access (TWA).

This is the name seen in the TWA portal, so it should be clear what types of architectural requests the form is for, especially if multiple forms are available at a property.

Description

Additional information for how the selected architectural request form is used. This is an internal reference and does not display in TWA.

Step 2: Customize and Add Sections

Each form has a default section already added. To rename the default Architectural Request Information header, next to Architectural Request Information click arrow_forward Edit. To add additional sections to the custom form, on the bottom of the page, click Add Section.

The following fields are available for each section:

Field Description

Title

The header name of the section on the form in Tenant Web Access (TWA). This also populates in the Fields section header below.

Alignment

Indicates how the fields in this section are aligned on the form in TWA (Left or Right).

Help Text

Any text to provide additional information about the section when the TWA user hovers over the title.

Description

Additional information regarding the purpose of the section.

Step 3: Customize Section Fields

Within each section, you can edit existing fields or add additional ones based on the needs of the form. To edit a field, next to the desired field, click  arrow_forward Edit. To add a new field to a section, click Add Field at the bottom of the section. Once all fields and options are established, click Add to add it to the form and close the pop-up, or click Save & Add More to add it to the form and leave the Add Field pop-up open to immediately add another field.

The following options are available by default when customizing field sections:

Option Description

Label

The name of the field as it displays on the form.

Help Text

Any text that provides additional information about the field when the TWA user hovers over the field's information icon.

Field Type

The control type, such as Text or Numeric, that determines what type of data can be entered into the field.

More Information

Each new architectural request form contains a system generated Architectural Request Information section. By default, the Request field in this section has a field type of Text and cannot be edited.

The following sections provide more information on the additional options you can select for each Field Type.

Attachments

The following fields are available when the Attachments field type is selected:

Field Description

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Minimum Required

The minimum number of attachments the TWA user must attach to the form. If there is no minimum number, leave this field blank.

Maximum Allowed

The maximum number of attachments the tenant can attach to the form. For example, if you enter 5, the TWA user can attach up to five attachments, but no more than that.

Date

The following fields are available when the Date field type is selected:

Field Description

Required

When checked, the form cannot be submitted until the field entry is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Dropdown

The following fields are available when the Dropdown field type is selected:

Field Description

Required

When checked, the form cannot be submitted until field is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Dropdown Options

The options available for the TWA user to select from. Enter an option into the field, then click . Repeat for every option that is available in the drop-down list. All options you add display in a list below the field. To change the order in which the options display in the list, select the desired item and click and drag to move it up or down in the list.

Multi Line Text

The following fields are available when the Multi Line Text field type is selected:

Field Description

Required

When checked, the form cannot be submitted until the field entry is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Minimum Length

The minimum character length that the TWA user must type to complete the field. For example, if you enter 50, the TWA user must type an answer at least fifty characters long (including spaces).

If the field is not set as Required, the TWA user can leave the field blank. If any characters are typed into the field, the minimum length is then enforced.

Maximum Length

The maximum character length that the TWA user can type into the field. For example, if you enter 300, the TWA user can type an answer up to three hundred characters long (including spaces), but not longer.

Number of Lines

The approximate height of the field based on the number of rows the field's text box should span across the form.

Numeric

The following fields are available when the Numeric field type is selected:

Field Description

Required

When checked, the form cannot be submitted until the field entry is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Minimum Value

The smallest acceptable numeric value for the field. For example, if you enter 20 and the TWA user submits a response of 13, the field is not considered complete and the form cannot be submitted.

If the field is not set as Required, the TWA user can leave the field blank. If any number is typed into the field, the minimum value is then enforced.

Maximum Value

The largest acceptable numeric value for the field. For example, if you enter 200 and the TWA user submits a response of 250, the field is not considered complete and the form cannot be submitted.

If the field is not set as Required, the TWA user can leave the field blank. If any number is typed into the field, the maximum value is then enforced.

Text

The following fields are available when the Text field type is selected:

Field Description

Required

When checked, the form cannot be submitted until the field entry is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Minimum Length

The minimum character length that the TWA user must type to complete the field. For example, if you enter 50, the TWA user must type an answer at least fifty characters long (including spaces).

If the field is not set as Required, the TWA user can leave the field blank. If any characters are typed into the field, the minimum length is then enforced.

Maximum Length

The maximum character length that the TWA user can type into the field. For example, if you enter 300, the TWA user can type an answer up to three hundred characters long (including spaces), but not longer.

Yes/No

The following fields are available when the Yes/No field type is selected:

Field Description

Required

When checked, the form cannot be submitted until the field entry is complete.

Column Span

The approximate width of the field based on the number of columns the field should span across the form.

Yes Display Text

If you wish to display an alternate text instead of the default Yes, enter the custom text here. For example, if you wish for the Yes option to display as Available on the form instead, enter Available.

This option applies only if Display As Drop-down is enabled.

No Display Text

If you wish to display an alternate text instead of the default No, enter the custom text here. For example, if you wish for the No option to display as Not Available on the form instead, enter Not Available.

This option applies only if Display As Drop-down is enabled.

Display As Drop-down

Enables the Yes and No options (or their custom alternatives) to display in a drop-down list on the form. Otherwise, the field displays as a toggle checkbox with the Label as the field name.

Step 4: Move Fields and Sections

Once you have created your desired form sections and fields, you can adjust where on the form they display. To move a section on the form, next to the section title, click arrow_forwardMove Section Up or Move Section Down.

If you have created a field on a section that you think would be a better fit in a different section of the form, next to field you want to move, select arrow_forward Move to Section, and select where to move the field.

Step 5: Save and Preview the Form

When you are finished creating the form, click Save. To preview what the architectural request form looks like for users in Tenant Web Access (TWA), click located in the action bar to the right. The fields can be interacted with so that you can simulate using the form the way a TWA user would.

Step 6: Assign Properties to the Form

When you are satisfied with your new form, return to the Architectural Request Forms page to assign the form to any applicable properties. This allows the form to be accessible in TWA for requests from the selected properties. To choose which properties have access to the form you created, next to the form you wish to assign, click arrow_forward Assign Properties.

More Information

Only properties with a Property Type of Association, as entered on the property's details page, display in the list.
