# Purchase Orders (Page)

Source: https://rmxhelp.rentmanager.com/Topics/Express/CSH/Purchase-Orders.htm

Purchase orders (POs) are used to request permission to purchase items, prevent unauthorized purchases, and maintain a historical record of items purchased. All POs are assigned statuses to identify rejected, approved, pending approval, or closed POs. You can also define PO workflows to automate the assignment of POs to selected users for review, approval, and fulfillment.

 Users who have the necessary privileges can approve purchase orders. Approved orders can be linked to bills and/or invoices. The data provided on the PO is used to populate related fields on bills and/or invoices. When items are received, the received quantity can be entered directly from the PO and automatically increase the number of available Inventory Items.

 Column Descriptions

 The following columns are available on this page. By default, some columns display only if added via . Additionally, you can sort some columns on the page to change the order in which the information displays in the list.

 DefaultColumn
 Description

 PO #

 The number entered or assigned by Rent Manager to each purchase order.

 Description

 The optional message entered in the Description field.

 Vendor

 The name of the vendor from whom you intend to purchase items.

 Requested By

 The user who created each purchase order.

 Request Date

 The date each purchase order was created.

 Approved By

 The user designated in the purchase order workflow that approved each purchase order. If a purchase order is not approved, then this field is blank.

 Status

 Displays whether the purchase order is awaiting approval, the items are approved to be purchased, the purchase order was closed, or the request to purchase items was rejected.

 The following status are available:

 Pending

 POs that are not yet approved or rejected.

 Approved

 POs that are approved.

 Rejected

 PO requisitions that were rejected and are inactive.

 Fulfilled

 POs for which all items are received.

 If the PO is closed, the last status before the PO was closed displays. For example, if the PO was closed while in the Approved status, the column displays Approved - Closed .

 Properties

 The property associated with each purchase order.

 Unit

 The unit associated with each purchase order. If no unit is associated with the purchase order, then this field is blank.

 Assigned To

 The user that the purchase order is currently assigned to.

 Available Column

 Description

 Approved Date

 Billing Address

 The address where bills are sent for purchased items.

 Cost Remaining

 The total cost of items that are not yet purchased for each purchase order.

 Create Date

 The date that each purchase order was created.

 Invoice #

 The invoice number for each purchase order that has a linked invoice.

 Issue Date

 The date when the associated service issue was created.

 Linked Bill

 The date and dollar amount for each purchase order with a linked bill(s).

 Property Short Name

 The shortened name of the property associated with each purchase order.

 Qty Remaining

 The number of items that need to be purchased for each purchase order.

 Shipping Address

 The address where the purchased items are shipped.

 Tenant

 The name of the tenant or owner each purchase order is associated with on the PO's details.

 Total Cost

 The total cost of all items included in a purchase order.

 Total Quantity

 The total number of items entered in each purchase order.

 Total Received

 The total number of items that were purchased and received for each purchase order.

 Update Date

 The most recent date that each purchase order was created or edited by a user.

 Workflow

 The name of the purchase order workflows assigned to each purchase order. If a workflow is not assigned, the field is blank.
